Project overview · tinyfleet

tinyfleet

Runs AI coding agents on your own projects, on your own machine: hands them work, sees it through review to the trunk, refuses dangerous commands, and keeps a record of every step. The binary is fleet.

01 · Direction

Where it is headed

Purpose and direction come from brain/prd/seed.md, which is the authority. Status lives on the board: bd show fleet-20ti.

02 · Architecture

How it fits together

There is no socket. The CLI and the controller only ever meet in the machine directory. One binary, three crates: cli depends on controller and core, controller on core, and core on nothing.

03 · What makes this hard

Seeing an agent from the outside

Agents are watched from outside, through tmux and the agent adapter's answers, so every reading can be missing or late, and "could not tell" is a first-class outcome everywhere. Simplified from the controller's table in controller/src/decide.rs, which also holds a halt latch and an arrival window.

05 · Invariants

What must stay true

Kind Invariant
domain Nothing lands on the trunk that its reviewer did not accept, and a landing never claims to be tested when it was not.
domain A person's notes on an item are theirs: tinyfleet never reads or writes them.
domain tinyfleet never commits to a person's project on its own, and never initialises or rewrites the project's work tracker.
domain Stopping tinyfleet never ends an agent's session, and retiring a seat never deletes its branch.
domain "Could not tell" is never reported as success.
architecture Looking at the fleet never changes it: status reads only what the controller published.
architecture The CLI and the controller meet only in the machine directory's files.
architecture Stores and agents are reached only through an adapter a pack ships; the binary carries none of its own.
architecture The binary carries only the defaults every fleet gets; roles, values and workflows come from packs.
architecture A run reads only the inputs pinned for it when it was opened.
code style core depends on no other crate, and never reads the process table.
code style A library crate never prints: clap, anyhow and the terminal crates belong to cli alone.
code style Only controller/src/platform/ names an operating system; only controller/src/host/tmux.rs names tmux.

directional Only the crate edges are checked by a test today, in cli/tests/workspace.rs. The rest become fitness tests in the pilot.
